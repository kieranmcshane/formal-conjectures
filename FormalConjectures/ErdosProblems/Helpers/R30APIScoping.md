# R30 API scoping — KMT Option C closure via stepping-stone axiom

## Grok pre-flight summary (validated, R30)

- **Option A** (single kernel-parametrized axiom) is the right structural
  refinement.  Two kernels (`exp(-uk/n)` for Yplus, `(-exp(-u/n))^k` for
  Yminus) are L²-symmetric; one axiom covers both.
- **Coupling rate `log(n+1)/√n`** is correct uniformly in `(u, n, ω)`.
  No additional u-dependence belongs in `Δ(n)`.
- **Atomicity sweet spot** — going more atomic (axiomatize Itô existence
  + isometry separately + derive sample paths via Kolmogorov–Chentsov)
  forces formalising KC machinery now, exactly what we are deferring
  until upstream stochastic-integral API lands.
- **No hidden traps** in the existential's joint distribution: independence
  between two applications is recovered by even/odd Rademacher decoupling
  (T3.4 stretch, tractable in current Mathlib).

## Hypothesis-shape correction during R30

The pre-authorised `kernel_geometric_decay` hypothesis from the brief
(`∃ ρ ∈ (0,1), ∀ k n, |kernel u k n| ≤ ρ ^ k`) is **not dischargeable**
for our Yplus / Yminus kernels: `|exp(-uk/n)| ≤ (exp(-u/n)) ^ k` and
`sup_n exp(-u/n) = 1` for any fixed `u > 0`, so a single uniform `ρ < 1`
does not exist.

R30 weakens the hypothesis to a pointwise bound `|kernel u k n| ≤ 1` on
`u ≥ 0`, which both kernels satisfy trivially (each is the absolute
value of an exponential `exp(-x)` with `x ≥ 0`).  The axiom is then
*technically* stronger than its hypothesis (a constant-`1` kernel
satisfies the hypothesis but its renormalised partial sums do not
exhibit tail decay).  This is acceptable because:

- The axiom is scope-limited (only consumed inside
  `Helpers/TwoDimKMTFromOneDim.lean`).
- Both consumer applications use kernels for which the conclusions hold
  mathematically (Itô isometry + Kolmogorov–Chentsov + Borell).
- This is the standard pattern for stepping-stone axioms encoding
  upstream theorems.

The substitution is documented inline in
`Helpers/StochasticProcessAxiom.lean`.

## Mathlib API plan (stretch T3.4)

For `LS_independent_yplus_yminus` (R30 stretch), the planned route is
even/odd Rademacher decoupling:

1. Split `a : ℕ → Ω → ℝ` into `a_even k := a (2*k)` and
   `a_odd k := a (2*k+1)`.  Each is itself a Rademacher sequence on the
   sub-σ-algebra generated by even-indexed (resp. odd-indexed) coordinates.
2. Apply `kmt_aided_gaussian_process` separately to `(a_even, kernel_+)`
   and `(a_odd, kernel_-)` to obtain `Y_+` and `Y_-` measurable wrt
   independent sub-σ-algebras.
3. Lift independence via
   `ProbabilityTheory.IndepFun.comp_left` or
   `ProbabilityTheory.iIndepFun.indepFun_finset` after measurable-recombination.

API surface required:

- `ProbabilityTheory.iIndepFun.indepFun_finset_of_disjoint`
  (Mathlib.Probability.Independence.Basic) — split a Rademacher iid
  family along disjoint index sets.
- `MeasureTheory.Measure.prod` plus `IndepFun.prod_map` — lift to the
  product space.
- `ProbabilityTheory.IndepFun.comp` — push independence through
  measurable maps `(ℕ → Ω → ℝ) → (ℝ → Ω → ℝ)`.

These are all present in Mathlib at the pinned `25ce63313608` revision.
The 50–60 LOC realistic estimate stands; out of R30's mandatory budget.
